A good bug report says which version you run (go list -m github.com/ysinghc/snowflake-lite), what you did, what you expected, and what happened. A minimal program is best.

Contribute

  1. Fork the repository and create a branch.
  2. Make a focused change. Match the style of the surrounding code.
  3. Run go vet ./... and go test -race ./.... Add a test for any behavior change.
  4. Open a pull request that explains what changed and why.

For anything larger than a small fix, open an issue first so we can agree on the approach before you invest time. The full guide is CONTRIBUTING.md.

Good first contributions

  • Documentation fixes. Every docs page has an “Edit this page” link.
  • Platform hardening from the known limitations list, such as authenticating the admin routes.
  • Making serve-saas read MACHINE_ID and DATACENTER_ID, as the Compose file and ConfigMap already assume.
  • Clients for other languages that call the platform API.

How decisions are made

The project is maintained by Yuvraj Singh Chauhan. Decisions happen in the open, in issues and pull requests. A change is merged when it has a clear rationale, passes CI, and keeps the core package small, dependency-free and lock-free. The core ID layout is a compatibility promise: changing it would invalidate existing IDs, so it only changes in a new major version.

Code of conduct

Be respectful and assume good faith. Harassment and personal attacks are not accepted. Maintainers may edit or remove comments and contributions that break these rules. The full text is in CODE_OF_CONDUCT.md.
