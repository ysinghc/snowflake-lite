Components

All security state lives in one object, SecurityManager, guarded by a single read-write mutex. It holds four things:

StatePurpose
API keysSHA-256 hash → tenant, tier, rate limit, permissions
BlocklistIP → expiry time. Expired entries are removed when next checked
Rate limitersOne token bucket per key or IP
Audit logThe last 1,000 events in a ring (oldest dropped)

API keys

  • A key looks like sk_live_<tier>_<16 hex characters>.
  • Only the SHA-256 hash is stored. Lookup hashes the presented key and reads the map, then compares the hashes in constant time.
  • Each key records a tenant, a tier, a rate limit and a permission list (ids:read, ids:batch, admin:all).

Rate limiting

Each caller gets a token bucket whose capacity and refill rate both equal its limit in requests per second. A request takes one token. When the bucket is empty the server replies 429 and tells the caller how long to wait. The identity is the key hash for authenticated calls and the client IP for anonymous ones.

Abuse protection

Before the bucket, the server records each request's time against its IP and keeps ten seconds of history. If an IP sends more than 500 requests in ten seconds while its limit is 100 or less (anonymous or free), it is blocked for 15 minutes and the event is logged as ABUSE_AUTO_BLOCK. Denied requests count too, so hammering an exhausted bucket trips the block.

Known limitations

These are properties of the current code, listed so you can decide whether it fits your environment. Contributions that address them are welcome; see Community.

Before a public deployment

Treat the platform server as a trusted-network service until the items below are resolved.

AreaCurrent behavior
Admin routes/api/v1/admin/* require no credentials. Anyone who can reach them can read metrics and audit logs, block or unblock IPs, and trigger the rebalance simulation
Key issuancePOST /api/v1/auth/keys is open, and the caller picks the tier, including enterprise
PermissionsPermission lists are stored but not checked. The generate routes accept any valid key
Client IPThe first value of X-Forwarded-For is trusted without checking the proxy, so a direct caller can spoof it to evade IP limits and blocks
Key randomnessKey material comes from math/rand, which is not cryptographically secure
Shared stateKeys, buckets and the blocklist are in memory per process. With several pods, a key created on one is unknown to the others, and limits apply per pod
Memory growthPer-IP and per-key limiter entries are never evicted
CORSAny origin is allowed on every route, including admin
TLSNone. Terminate TLS at an ingress or proxy

The core library

None of the above affects the snowflake package. It has no network code, no global state and no dependencies. See Security for how to report a vulnerability.
