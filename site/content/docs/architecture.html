The arrows point from user to dependency. wasm and cmd/snowflake depend on snowflake directly; nothing depends on cmd or wasm. The core package imports only the standard library and knows nothing about HTTP, so it stays small enough to read in one sitting.

The core package

A single file, snowflake/snowflake.go, with about 215 lines. It defines the layout constants, the ID and Parts types, the constructors, and Generator.Next. A compile-time check, var _ = [1]struct{}{}[63-(timestampBits+machineBits+sequenceBits)], fails the build if the three field widths ever stop summing to 63. The clock is a function field, now, so tests can simulate skew without sleeping.

The platform package

FileResponsibility
engine.goMultiEngine: generates and decodes the five formats
security.goSecurityManager: keys, token buckets, blocklist, audit log
metrics.goMetricsCollector: counters, percentiles, node list
server.goServer: routes, middleware and handlers that tie the three together

A Server owns one of each. Handlers never touch the maps inside the managers; they call methods, and the managers lock for themselves.

Concurrency model

StateProtection
Snowflake and custom generatorsOne atomic word each, compare-and-swap
ULID last timestamp and random bytesA mutex (ulidMu)
Security maps and audit logOne RWMutex in SecurityManager
Per-second counters, latency samples, nodesAn RWMutex in MetricsCollector; the grand total is an atomic

The browser build

wasm/main.go compiles to WebAssembly with GOOS=js GOARCH=wasm and registers five global functions: snowNew(machine), snowNext(), snowNextBatch(n) (up to 200,000), snowBench(n) and snowDecode(idString). It calls onSnowReady when they are bound. IDs cross the boundary as strings because of the 253 limit. A native stub, wasm/stub.go, lets go build ./... succeed on a normal machine. The demo on the home page is this build.
