The project is one Go module, github.com/ysinghc/snowflake-lite, with no third-party dependencies. Only the snowflake package is meant to be imported.

The library

A single file, snowflake/snowflake.go, of about 215 lines. It defines the layout constants, the ID and Parts types, the constructors, and Generator.Next. It imports only the standard library and knows nothing about HTTP, so it is small enough to read in one sitting. Two details are worth knowing:

  • A compile-time check, var _ = [1]struct{}{}[63-(timestampBits+machineBits+sequenceBits)], fails the build if the three field widths ever stop summing to 63.
  • The clock is a function field, now, so tests can simulate skew without sleeping.

Concurrency is handled by one atomic word per generator. See How it works for the algorithm, and the code map for every function and its callers.

The browser build

wasm/main.go compiles to WebAssembly with GOOS=js GOARCH=wasm and registers five global functions: snowNew(machine), snowNext(), snowNextBatch(n) (up to 200,000), snowBench(n) and snowDecode(idString). It calls onSnowReady when they are bound. IDs cross the boundary as strings because of the 253 limit. A native stub, wasm/stub.go, lets go build ./... succeed on a normal machine. The playground on the home page is this build.

The website

site/build.sh produces everything the site serves that comes from the Go source:

StepOutput
Compile wasm/snowflake.wasm for the playground
Run site/tools/funcmapfuncmap.json, the call graph behind the code map
Run site/build-pages.mjsHTML pages assembled from site/content/

A Cloudflare Worker (site/src/worker.js) serves these files and fills in the latest release version from the repository's public release feed, cached for five minutes. Tagging a release therefore updates the site without a redeploy.
