Container image

The Dockerfile builds in two stages: a Go 1.23 Alpine builder produces a static, stripped binary, and a minimal Alpine 3.19 image carries only that binary and the web directory. It listens on port 8080 and starts snowflake serve-saas --addr :8080. No image is published; build it yourself:

docker build -t snowflake-saas .
docker run --rm -p 8080:8080 -e POD_NAME=snowflake-worker-0 snowflake-saas

Machine IDs

The one rule of the library applies here too: every running server needs a distinct machine ID. serve-saas chooses it like this:

  1. If --machine is non-zero, use it.
  2. Otherwise take the name from $POD_NAME, or the hostname if that is empty, split it on -, and use the trailing number. snowflake-worker-2 becomes machine 2.
  3. Otherwise the machine ID is 0.
Environment variables

serve-saas does not read MACHINE_ID or DATACENTER_ID, although the Compose file and the Kubernetes ConfigMap set them. In those setups the machine ID works because the pod name ends in the ordinal, and the datacenter stays 0. Pass --machine or --datacenter explicitly if you need other values.

A pod name that does not end in a number gets machine 0, and a number above 1023 stops the server at start-up.

Docker Compose

docker-compose.yml runs three workers, named snowflake-worker-0 to -2, on host ports 8080 to 8082, each with a /healthz health check and restart: always.

docker compose up --build
curl localhost:8081/api/v1/ids/generate

The workers are independent processes. They do not share keys or rate-limit state.

Kubernetes

The k8s directory holds the manifests:

FileWhat it defines
deployment.yamlA StatefulSet of 3 replicas, a ClusterIP service on port 80, and a headless service. Pods get their name from the downward API; anti-affinity spreads them across nodes; probes use /healthz and /readyz; requests 100m CPU / 64Mi, limits 1 CPU / 256Mi
hpa.yamlScales between 3 and 20 replicas at 75% CPU or 80% memory. Scale-up is immediate (up to +100% per 15 s); scale-down waits 5 minutes and removes at most 10% per minute
configmap.yamlDATACENTER_ID, CUSTOM_EPOCH, DEFAULT_RATE_LIMIT, LOG_LEVEL. Only DATACENTER_ID is referenced by the StatefulSet, and the server ignores it (see above)
ingress.yamlAn nginx ingress for id.snowflake-saas.local with 5-10 s timeouts and a 5,000 requests-per-second limit
cluster-autoscaler-config.yamlNode autoscaler settings

Why a StatefulSet

A StatefulSet gives each pod a stable ordinal name that survives restarts, and the ordinal is the machine ID. A Deployment would give random names and break the scheme. Scaling to 20 replicas uses machine IDs 0 to 19, far below the 1,023 ceiling.

kubectl apply -f k8s/
kubectl get pods -l app=snowflake-saas

The manifest uses the image name snowflake-saas:latest with IfNotPresent; push your build to a registry and change it.

Checklist

  • Distinct machine ID per instance.
  • TLS terminated in front of the server.
  • Admin and key-issuance routes blocked at the ingress (see Security model).
  • A reverse proxy that overwrites X-Forwarded-For.
